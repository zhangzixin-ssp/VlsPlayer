1. このマニュアルが解決する課題

Anki のメディアファイルは、iPhone 上ではデスクトップや Android とまったく異なる扱いになります。デスクトップと Android ではファイルマネージャで直接メディアフォルダを操作できますが、iPhone ではできません。iOS のサンドボックス機構により、AnkiMobile のメディアライブラリはユーザーに完全に閉じられています。

その結果、いくつかの現実的な問題が生じます：

  1. 数十 GB のメディアを iPhone にどう入れるか？ AnkiWeb 同期は不可能です。唯一現実的な方法は apkg によるオフラインパッケージで、iTunes ファイル共有またはクラウド経由で転送します。
  2. Windows で動画をどう再生するか？ Windows 版 Anki は WebM のみ対応で MP4 は非対応です。同じ動画を 2 種類用意する必要があります：iPhone 用 MP4、Windows 用 WebM。
  3. iPhone 上でメディアを正確にシークさせるには？ すべての動画フォーマットがシークに対応しているわけではありません。条件を満たさないファイルは iPhone で再生はできても、プログレスバーがおかしくなります。
  4. すでにインポートしたメディアをどう削除するか？ Anki の「メディアをチェック」は未使用メディアをクリーンアップできますが、[sound:] 参照がなくなっている必要があり、かつ 100MB 未満である必要があります。
  5. apkg のインポートがいつも失敗するのはなぜ？ iPhone 上に同名 deck が既に存在し、AnkiMobile は上書きしないためです。旧 deck を削除してからインポートする必要があります。

このマニュアルでは、これらの問題に対する完全で実行可能な手順を示します。

2. 3 プラットフォームの本質的な違い

2.1 比較表

プラットフォームメディアファイルへのアクセス動画フォーマットメディアパック必要？
Windowscollection.media フォルダを直接開ける。追加・削除・置換自由WebM のみ不要
macOScollection.media フォルダを直接開けるMP4 / WebM不要
AndroidAnkiDroid のメディアフォルダに直接アクセスMP4不要
iPhone / iPadサンドボックス化され、ファイルシステムにアクセス不可MP4必須

2.2 デスクトップと Android の通常手順

  • メディアファイルを collection.media に直接コピー
  • カード内の [sound:] 参照が自動的にファイルを見つける
  • 削除はそのままファイルを削除
  • 置換はそのままファイルを上書き
  • メディアをチェックが正常動作

2.3 iPhone の困難

本マニュアルは iPhone / iPad を対象としています。デスクトップと Android ユーザーはメディアフォルダを直接操作できます。Windows の WebM 制限にだけ注意してください。

iPhone のサンドボックス機構による影響：

  • ファイルシステムにアクセス不可 → 手動でコピー・削除・置換できない
  • メディア転送路は apkg のみ → メディアをパッケージしないと端末に入らない
  • [sound:] が Anki にファイルをパッケージさせる唯一の手段
  • メディア削除は「メディアをチェック」に依存し、[sound:] 参照の削除でトリガーされる
  • apkg インポート前に同名 deck を削除しないと、インポートがスキップされる

3. Windows の動画フォーマット制限

Windows 版 Anki は WebM 動画のみ対応、MP4 は非対応です。これは Windows 版 Anki の再生エンジンの制限で、iPhone とは無関係です。

3.1 この制限の理由

Windows 上の Anki は QtWebEngine（Chromium ベース）を使用しています。Chromium は Windows では H.264 デコーダを標準搭載していないため（特許ライセンスの問題）、MP4 は再生できません。WebM は VP8/VP9 を使用し、オープンで無料のため対応しています。

3.2 ワークフローへの影響

同じ動画に対して 2 バージョンが必要です：

プラットフォーム動画フォーマットコーデック
iPhone / iPad / Android / macOSMP4H.264 + AAC
WindowsWebMVP8/VP9 + Vorbis/Opus

3.3 メディアパック deck の分割

これがメディアパックをフォーマット別にグループ化する理由です。Seinfeld の例：

0. Resources/
├── MP4 Seinfeld/     (iPhone / Android / macOS 用)
│   ├── Seinfeld S01 Mp4
│   ├── Seinfeld S02 Mp4
│   └── ...
└── WEBM Seinfeld/    (Windows 用)
    ├── Seinfeld S01 Webm
    ├── Seinfeld S02 Webm
    └── ...

2 つの deck は独立して準備し、それぞれ apkg にエクスポートして対応プラットフォームへ転送します。

3.4 オーディオは影響を受けない

オーディオは Windows でも制限が少なく、MP3 も M4A も再生できます。そのため MP3 シリーズは 1 部だけで済みます。

4. 中核機構：[sound:] の役割

4.1 よくある誤解

多くの人は [sound:] を再生制御のためだと思っています。メディア転送の文脈では、その真の目的は：

Anki が apkg をエクスポートする際に対応するメディアファイルをパッケージに含めるようにすることです。

4.2 必須である理由

Anki は apkg をエクスポートする際、カード内のすべての [sound:] と <img> 参照をスキャンし、それらが指すメディアファイルを収集してパッケージ化します。参照されていないファイルは、Anki がこの deck に属していると認識できないため、パッケージに含まれません。

数十 GB のメディアでは特に重要です：

  • AnkiWeb 同期は不可能（帯域、1 ファイル 100MB 制限）
  • apkg が唯一信頼できる一括オフライン転送手段
  • そして apkg は [sound:] 経由でしかメディアを宣言できない

4.3 [sound:] の 3 つの役割

役割説明
転送宣言これらのファイルを apkg に含めるよう Anki に指示
クリーンアップスイッチ[sound:] を削除して再インポートすると、そのファイルは「未使用」になり、「メディアをチェック」で削除可能になる
上書きトリガー同名ファイルを上書きする場合、Anki は [sound:] で参照されるファイルのみ認識する

4.4 [sound:] は再生制御を担当しない

再生制御は実際にはカードテンプレートの JavaScript が担当します（VlsPlayer Series / Notes マニュアル参照）。ここでの [sound:] は単なる「ファイルリスト」です。

5. メディアパック deck の構造

5.1 設計原則

  • シリーズごとに 1 deck：個別にエクスポート・転送・クリーンアップしやすい
  • シーズンごとに 1 カード：シーズン番号があるシリーズはシーズンごとにカード
  • シーズン番号がないシリーズは 1 カードで全体を表現
  • フォーマット別にグループ化：MP3 / MP4 / WEBM を分離し、プラットフォーム別に使いやすく
  • deck 名とフィールド名は純英語：Unicode パスの問題を避ける

5.2 推奨構造（シーズンあり）

Seinfeld の例：

0. Resources/
├── MP4 Seinfeld/
│   ├── Seinfeld S01 Mp4   (カード1、sound フィールドに S01 の全エピソード)
│   ├── Seinfeld S02 Mp4   (カード2、sound フィールドに S02 の全エピソード)
│   ├── Seinfeld S03 Mp4
│   ├── ...
│   └── Seinfeld S09 Mp4
└── WEBM Seinfeld/
    ├── Seinfeld S01 Webm
    └── ...

5.3 推奨構造（シーズンなし）

Atomic Habits の例：

0. Resources/
├── MP3 Atomic Habits      (1 deck、1 カード)
├── MP3 CWE                (1 deck、1 カード)
├── MP4 DDM
└── MP4 Friends

5.4 カードフィールド

各ノートには 2 つのフィールドがあります：

フィールド内容
Front識別子としての 1 行のプレーンテキスト、例 Seinfeld S02 Mp4
sound1 行に 1 つの [sound:xxx]、このカードの全メディアを列挙

5.5 sound フィールドの例

シーズンあり（Seinfeld S02）：

[sound:sf_s02e01.mp4]
[sound:sf_s02e02.mp4]
[sound:sf_s02e03.mp4]
...
[sound:sf_s02e12.mp4]

シーズンなし（CWE）：

[sound:cwe_01.mp4]
[sound:cwe_02.mp4]
[sound:cwe_03.mp4]
...
各 [sound:] は 1 行ずつ記述してください。読みやすく、編集しやすいです。1 行にまとめないでください。後で保守しにくくなります。

5.6 なぜシーズンごとに 1 カードか

利点説明
サイズ管理1 シーズンの apkg は大きすぎず、転送が安定
独立更新あるシーズンの更新はそのカードのみ再エクスポート
独立クリーンアップシーズン単位でクリーンアップでき粒度が明確
命名が明快Front フィールドでシーズンが一目で分かる

6. ファイル命名規則

6.1 2 つの命名パターン

内容にシーズン番号があるかどうかで分かれます：

シーズンなし

接頭辞_エピソード番号.拡張子

例：

cwe_01.mp4
cwe_02.mp4
atomic_habits_00.mp3
atomic_habits_01.mp3

シーズンあり

接頭辞_sシーズンeエピソード.拡張子

例：

sf_s02e01.mp4
sf_s02e02.mp4
sf_s02e12.mp4

6.2 規則

項目規則
接頭辞シリーズ略号、2〜4 文字の小文字、例 sf、cwe、ah
区切りアンダースコア _
シーズンs + 2 桁ゼロ埋め、例 s01、s02（シーズンありのみ）
エピソードe + 2 桁ゼロ埋め、例 e01、e12（シーズンありのみ）
エピソード（シーズンなし）2 桁または 3 桁ゼロ埋め、例 01、001
拡張子統一。シリーズ内で混在させない
禁止中国語、スペース、大文字、特殊文字

6.3 桁数の決め方

  • 100 話未満 → 2 桁（01 ~ 99）
  • 100 話以上 → 3 桁（001 ~ 999）
  • 桁数は必ず統一。統一しないと並び順が崩れます：_9.mp4 は _10.mp4 の後に並びます

6.4 同一シリーズで複数フォーマット

sf_s02e01.mp4   (iPhone / Android / macOS)
sf_s02e01.webm  (Windows 用)
sf_s02e01.mp3   (オーディオ)

ファイル名は同じで拡張子だけ異なります。カード内の参照構造は一貫しているため、プラットフォーム別に拡張子を差し替えるだけで済みます。

6.5 VlsPlayer Series カードとの整合性

この命名規則は Series カードの Timeline フィールドの連結規則と必ず一致させる必要があります。Series カードのコードでは：

ファイル名 = 接頭辞 + "_" + (シーズン == "" ? エピソード : "s" + シーズン + "e" + エピソード) + 拡張子
  • シーズンなし → cwe_01.mp4
  • シーズンあり → sf_s02e01.mp4
メディアパック deck の [sound:] 参照、Series カードの Timeline フィールド、実際のファイル名は完全一致している必要があります。そうでないとカードがファイルを見つけられません。

6.6 [sound:] 参照の一括生成

シーズンあり（Bash、1 シーズン 12 話の場合）：

for i in $(seq -w 1 12); do echo "[sound:sf_s02e${i}.mp4]"; done

シーズンなし：

for i in $(seq -w 1 30); do echo "[sound:cwe_${i}.mp4]"; done

出力をそのまま sound フィールドに貼り付けてください。

7. ffmpeg による圧縮と変換

7.1 圧縮が必要な理由

  • 元動画は数十 GB になることが多く、iPhone には収まらない
  • Anki は 1 ファイル 100MB の処理制限がある
  • AnkiMobile は大きいファイルの読み込みで動作が重くなる
  • 語学学習には字幕と口の動きが見えれば十分。画質の細部は不要

7.2 動画圧縮：高さのみ指定すればよい

幅を指定する必要はありません。-2 を使って ffmpeg に自動計算させます：

MP4（iPhone / Android / macOS）

ffmpeg -i input.mkv \
  -vf "scale=-2:270" \
  -c:v libx264 -profile:v main -level 3.0 -preset fast -crf 28 \
  -c:a aac -b:a 64k -ac 1 \
  -movflags +faststart \
  output.mp4

WebM（Windows 用）

ffmpeg -i input.mkv \
  -vf "scale=-2:270" \
  -c:v libvpx-vp9 -crf 35 -b:v 0 \
  -c:a libopus -b:a 64k -ac 1 \
  output.webm

scale=-2:270 の意味：

  • 高さを 270 に固定
  • 幅は自動計算され、アスペクト比を保持
  • -2 は幅が偶数になることを保証（エンコーダの要件）

270 は iPhone にもデスクトップにも十分で、字幕と口の形がはっきり見えます。幅は ffmpeg に任せましょう。元が 16:9 か 4:3 かを気にする必要はありません。

7.3 オーディオ圧縮

推奨は M4A：

ffmpeg -i input.wav \
  -c:a aac -b:a 64k -ac 1 \
  -movflags +faststart \
  output.m4a

どうしても MP3 を使う場合は CBR（固定ビットレート）で：

ffmpeg -i input.wav \
  -c:a libmp3lame -b:a 64k -ac 1 \
  output.mp3
-q:a を付けないでください。VBR（可変ビットレート）になり、Xing ヘッダがない VBR MP3 は iPhone でシークが不正確になります。

7.4 主要パラメータ

パラメータ効果
scale=-2:270高さ 270 固定、幅は偶数で自動
-profile:v mainH.264 main profile、iOS 互換
-level 3.0互換性の余裕
-crf 28画質/サイズのバランス点。これより大きいとぼやける
-b:a 64k -ac 1モノラル、64 kbps
-movflags +faststartMP4 専用。moov を先頭に移動。iPhone での正確なシークに必須。

WebM には -movflags +faststart は不要です（MP4 専用）。

7.5 まだ大きい場合

さらなる圧縮：

  • -crf 32 — 画質を 1 段下げる
  • scale=-2:180 — 高さを 180 に
  • -r 20 — フレームレートを 20 fps に
  • -b:a 48k — オーディオを 48 kbps に

7.6 バッチ変換スクリプト

Windows バッチ（同じフォルダの全 mkv を mp4 に）：

for %%f in (*.mkv) do (
  ffmpeg -i "%%f" -vf "scale=-2:270" ^
    -c:v libx264 -profile:v main -level 3.0 -preset fast -crf 28 ^
    -c:a aac -b:a 64k -ac 1 ^
    -movflags +faststart "%%~nf.mp4"
)

同じフォルダで webm に：

for %%f in (*.mkv) do (
  ffmpeg -i "%%f" -vf "scale=-2:270" ^
    -c:v libvpx-vp9 -crf 35 -b:v 0 ^
    -c:a libopus -b:a 64k -ac 1 ^
    "%%~nf.webm"
)

8. メディアは正確にシーク可能であること

8.1 「シーク可能」とは

シークとは、プレイヤーがファイル内の任意の時点にジャンプして再生できることです。iPhone 上の AVFoundation のシーク対応は、コンテナフォーマットとメタデータ構造に依存します。

シーク不可能なファイルでは：

  • 再生はできるが、プログレスバーが不正確
  • 中間へのジャンプでスタック、または先頭に戻る
  • 複数の [sound:] を連続再生すると 2 つ目の開始位置がずれる
  • ループの開始位置がずれる

8.2 フォーマット別のシーク条件

フォーマットシーク条件満たさない場合
MP4 / M4Amoov atom がファイル先頭ファイル全体を読まないとシークできない。大きいファイルでは事実上不可能
WebMiOS AVFoundation の対応不完全iPhone でシーク不可、Windows では問題なし
MP3 (VBR)Xing/Info ヘッダが必要シーク位置が不正確
MP3 (CBR)本来シーク可能—
OGG / OpusiOS 非対応再生不可
AVI / MKV / WMV / FLViOS 非対応再生不可
H.264 + AAC in MP4最も安定—

8.3 シーク可能にする 4 つの原則

  1. iPhone：動画は MP4（H.264 + AAC）、音声は M4A または CBR MP3
  2. -movflags +faststart で moov を先頭に。ないと大きいファイルはシーク不可
  3. 動画 profile は新しすぎないこと。baseline / main が最安定
  4. オーディオのサンプルレートは 44.1 kHz または 48 kHz に統一

8.4 検証方法

ffprobe で moov の位置を確認：

ffprobe -v trace -i output.mp4 2>&1 | grep -E "type:'moov'|type:'mdat'"

moov が mdat より先に来れば faststart 処理済みです。

8.5 ひとことまとめ

iPhone：動画は H.264 main profile + AAC の MP4 で必ず -movflags +faststart を付ける。Windows：動画は VP9/VP8 + Opus/Vorbis の WebM。音声はすべて AAC M4A、または CBR MP3。

9. apkg にパッケージする

9.1 デスクトップ側の準備

  1. 変換済みのメディアファイルを collection.media に配置
  2. メディアパック deck（例 MP4 Seinfeld）を開く
  3. sound フィールドの [sound:] 参照が実ファイルと一致しているか確認
  4. Anki の「メディアをチェック」で全参照が解決できるか確認

9.2 エクスポート

  1. deck 一覧で対象 deck を右クリック → エクスポート
  2. 「Anki デッキパッケージ（.apkg）」を選択
  3. 「メディアを含める」にチェック
  4. 保存先を選択
あるシリーズやシーズンだけをエクスポートしたい場合は、その deck だけを選択してください。「すべてのデッキ」は選ばないでください。シーズン単位でエクスポートすると、転送とインポートがより確実です。

9.3 パッケージの検証

  • apkg サイズがメディアファイル合計に近いこと
  • apkg が明らかに小さい場合はメディアが含まれていない。[sound:] 参照を確認
  • 7-Zip で apkg を開いて（実際は zip）collection.media にファイルがあるか確認

10. iPhone へ転送

転送するのは apkg ファイルそのものです。同期メディアではありません。メディアは apkg にパッケージされ、一括で iPhone に転送されます。AnkiWeb を経由しません。

10.1 3 つの方法

方法適した場面利点
iTunes / Finder ファイル共有Windows / Mac、第一候補有線、最も安定、サイズ制限なし
クラウドドライブケーブルがないときアップロード後 iPhone でダウンロード、便利
AirDropMac、中小サイズの apkgオフライン可、速い
USB ドライブ大容量 apkg（> 5GB）ネット不要、最も安定

10.2 iTunes / Finder ファイル共有（第一候補）

最も一般的な方法で、ネットワークに依存せず、apkg のサイズ制限もありません。

Windows（iTunes）

  1. ケーブルで iPhone と PC を接続
  2. iTunes を開き、デバイスアイコンをクリック
  3. 「ファイル共有」へ
  4. アプリ一覧で AnkiMobile を選択
  5. 「ファイルを追加」をクリックし apkg を選択
  6. iTunes が apkg を AnkiMobile の Documents へコピー
  7. iPhone で AnkiMobile を開くと apkg がインポート一覧に現れる

macOS（Finder）

  1. ケーブルで iPhone と Mac を接続
  2. Finder を開き、サイドバーの iPhone をクリック
  3. 「ファイル」タブへ
  4. アプリ一覧で AnkiMobile を選択
  5. apkg をファイルリストにドラッグ
  6. iPhone で AnkiMobile を開いてインポート

10.3 クラウドドライブ

よく使われるもの：iCloud Drive、OneDrive、Google Drive、Baidu Netdisk、Nutstore。

  1. PC で apkg をクラウドにアップロード
  2. iPhone でクラウドアプリを開き、apkg をダウンロード
  3. apkg をタップ → AnkiMobile で開く
  4. または「ファイル」アプリに保存してからタップしてインポート
Baidu Netdisk など中国のクラウドでは、「別のアプリで開く」を選んで AnkiMobile を選択する必要があるかもしれません。iOS がファイルを AnkiMobile に引き渡します。

10.4 AirDrop（Mac ユーザー）

  1. Mac で apkg を右クリック → 共有 → AirDrop
  2. iPhone を選択
  3. iPhone で「受け入れる」をタップ
  4. iOS がどのアプリで開くか尋ねるので AnkiMobile を選択

10.5 USB ドライブ（大容量ファイル）

  1. apkg を USB-C または Lightning の USB ドライブにコピー
  2. ドライブを iPhone に接続
  3. 「ファイル」アプリを開き USB ドライブへ
  4. apkg をタップ → AnkiMobile で開く

11. インポート：先に旧 deck を削除

最もよくある落とし穴です。iPhone 上に同名 deck が既にあると、apkg インポートは失敗するかスキップされます。先に旧 deck を削除してください。

11.1 なぜ先に削除するのか

AnkiMobile は apkg をインポートする際、同名 deck に対して既存ノートをスキップする方針で、上書きはしません。つまり：

  • 同名 deck が存在 → 新ノートはインポートされない
  • 既存ノートは更新されない
  • メディアファイルも置換されない

結果として、新しい apkg をインポートしても iPhone には古い内容が残ります。

11.2 正しいインポート手順

  1. AnkiMobile で該当する旧 deck を探す
  2. deck を長押し → 削除（またはスワイプで削除）
  3. 削除を確認
  4. apkg ファイルをタップ → AnkiMobile で開く
  5. deck 名とカード数が表示される確認ダイアログが出る
  6. 「インポート」をタップして完了を待つ

11.3 deck を削除すると学習進捗が失われる？

  • メディアパック deck（1 枚のカード、レビューしない）なら影響なし
  • 学習カードがメディアを参照している場合、メディアパック deck の削除は影響しない
  • 学習 deck を削除するとスケジュール進捗が失われるので、事前に確認

11.4 一括削除

複数シーズンの deck を更新する場合：

  1. 更新対象の deck をまとめて削除
  2. 新しい apkg を順番にインポート

11.5 成功の確認

  • 新しくインポートした deck を開きカード数を確認
  • メディアパックカードの sound フィールドで [sound:] が再生可能か確認
  • 学習カードを開きメディアを再生、プログレスバーをドラッグしてシーク確認

11.6 インポート後の整理

インポート完了後、転送に使った apkg のコピー（USB ドライブ、クラウド、iTunes 内）を削除して容量を空けられます。

12. メディアの更新

12.1 更新が必要な場面

  • 動画の切り出し位置が間違っていたので切り直し
  • 圧縮パラメータが不適切だったので圧縮し直し
  • 字幕タイムラインが変わりメディアを再生成
  • 新しいエピソードを追加

12.2 更新手順

  1. デスクトップ側で新しいメディアファイルを生成
  2. ファイル名は変えずに、collection.media の旧ファイルを上書き
  3. sound フィールドの参照に変更が不要か確認（ファイル名が同じなら不要）
  4. 「メディアを含める」にチェックして apkg を再エクスポート
  5. iPhone へ転送
  6. 先に iPhone 上の旧 deck を削除
  7. 新しい apkg をインポート
メディアは同期しません。更新は「旧 deck 削除 → apkg 再インポート」でのみ行います。1 ファイルだけ同期する、という操作は存在しません。

12.3 メディアの追加

  1. 新しいファイルを命名規則に従って命名、例 sf_s02e13.mp4
  2. collection.media に配置
  3. sound フィールドの末尾に [sound:sf_s02e13.mp4] を追加
  4. apkg を再エクスポート
  5. iPhone 上の旧 deck を削除
  6. 新しい apkg をインポート

12.4 ファイル名の変更

ファイル名変更は高リスクです。iPhone 上に旧ファイルが残留します。必要な場合を除いて避けてください。変更する場合：
1. 新しいファイル名を規則に従って命名
2. カードの参照も更新
3. apkg を再エクスポート
4. 旧 deck を削除して再インポート
5. 旧ファイルはセクション 13 の方法でクリーンアップ

13. 特定のメディアファイルを削除

このセクションのテクニックが本マニュアルの中核です：[sound:] 参照を削除することで、Anki の「メディアをチェック」をトリガーし、iPhone 上のそのファイルをクリーンアップします。

13.1 原理

Anki の「メディアをチェック」はメディアライブラリ全体をスキャンし、どのカードからも参照されていないファイルを見つけて「未使用ファイル」にリストし、削除を許可します。

したがって、以下を行うだけで：

  1. カードフィールドから対応する [sound:xxx.mp4] を削除
  2. apkg を再エクスポートして iPhone にインポート（先に旧 deck を削除）
  3. AnkiMobile で「メディアをチェック」を実行
  4. そのファイルが「未使用ファイル」に現れ、削除できる

13.2 完全な手順

ステップ 1：sound フィールドの参照を削除

デスクトップ Anki でメディアパック deck のカードを開き、sound フィールドから [sound:xxx.mp4] の行を削除します。

ステップ 2：他の参照がないことを確認

Anki の検索でコレクション全体を xxx.mp4 で検索：

検索ボックス：xxx.mp4

結果がまだある場合、他のカードが使用中なので削除できません。

ステップ 3：apkg を再エクスポート

メディアパック deck を再エクスポートします。参照がなくなったので、Anki はそのファイルを含めません。

ステップ 4：iPhone へ転送

iTunes ファイル共有 / クラウド / AirDrop / USB で転送。

ステップ 5：iPhone 上の旧 deck を削除

AnkiMobile で対応する旧 deck を見つけて削除。

ステップ 6：新しい apkg をインポート

新しい apkg をタップして AnkiMobile でインポート。

ステップ 7：「メディアをチェック」を実行

AnkiMobile（またはデスクトップ Anki）で「メディアをチェック」を実行。参照のないファイルは「未使用ファイル」に表示されます。

ステップ 8：未使用ファイルを削除

確認して削除。容量が解放されます。

13.3 なぜこれが機能するか

AnkiMobile の「メディアをチェック」はローカルのメディアライブラリをカード参照と照合し、孤立ファイルを見つけます。ファイルが参照されなくなれば、サイズに関係なく「未使用」として扱われます。

13.4 注意事項

  • ファイルが 100MB 未満であることが前提です。100MB 超のファイルは「未使用」判定に参加しません。セクション 14 参照
  • 参照を削除した後、カードでそのメディアを再生すると「メディアが見つかりません」と表示されますが、これは想定内です
  • 欠落警告を避けたい場合は、カードも削除するかクリーンアップしてください
  • 作業前に apkg をバックアップしてください
  • iPhone の「メディアをチェック」でファイルが見つからない場合、インポートが失敗した可能性があります。再インポートしてください

13.5 複数メディアの一括削除

複数のファイルをクリーンアップする場合、対応する [sound:] 行を一度にすべて削除し、apkg を再エクスポートしてインポート後、「メディアをチェック」を 1 回実行します。

14. 100MB 超の大ファイルをクリーンアップ

14.1 問題

メディアファイルが 100MB を超える場合、参照カードを削除しても、ファイルはメディアライブラリに残り、「メディアをチェック → 未使用ファイルを削除」で削除できません。

14.2 根本原因

Anki の「メディアをチェック」は 100MB 超のファイルを特別扱いします：

  • 「100MB 超のファイル」として別リストに分類
  • 「未使用ファイル」の判定に参加しない
  • カードがまだ参照しているかどうかに関わらず、内蔵機能では削除できない

この設計の起源は、AnkiWeb の 1 ファイル 100MB の同期上限です。Anki はこのようなファイルは手動で扱うと想定しています。

14.3 回避策

同名の極小ファイルで上書きして 100MB 未満に落とします。すると Anki は普通のファイルとして扱い、どのカードからも参照されていなければ「未使用ファイル」に分類され、削除できるようになります。

14.4 完全な手順

ステップ 1：カード参照を削除

デスクトップ Anki で、カードフィールドから [sound:xxx.mp4] 参照を削除するか、カードごと削除します。

ステップ 2：同名の極小ファイルを準備

元ファイルと同名で、100MB よりはるかに小さいファイルを作成します。

Windows：

type nul > xxx.mp4

または ffmpeg で 1 秒の無音を生成：

ffmpeg -f lavfi -i anullsrc=r=44100:cl=mono -t 1 -c:a aac -movflags +faststart xxx.mp4

ステップ 3：collection.media の元ファイルを上書き

デスクトップ Anki のメディアフォルダを開き（ツール → メディアをチェック → ファイルを表示）、準備した極小ファイルをコピーして元の大ファイルを上書きします。

ステップ 4：apkg を再エクスポート

そのシリーズ（またはメディアパック deck）を「メディアを含める」で再エクスポートします。

ステップ 5：iPhone へ転送して再インポート

iTunes ファイル共有 / クラウドで iPhone へ。

先に iPhone 上の旧 deck を削除してから、新しい apkg を AnkiMobile でインポートします。同名の極小ファイルが iPhone 上の大ファイルを上書きします。

ステップ 6：メディアをチェック

ファイルは 100MB 未満になり「未使用ファイル」に現れます。削除して容量を解放します。

14.5 同名上書きが機能する理由

Anki のメディアライブラリはファイル名で管理されています。同名ファイルを使うと、Anki はインポート時点で同名ファイルが存在することを検知し、新しいファイルで置換します。元の大ファイルは消えます。

14.6 前提条件

  • カードがそのファイルを参照していないこと。参照が残っていると、ファイルが小さくなっても Anki は「使用中」と見なし削除しません
  • 上書きはデスクトップで行う。AnkiMobile のメディアフォルダには直接アクセスできません
  • iPhone 上のファイルが置換されない場合、インポートが失敗した可能性があります。再インポートしてください

14.7 警告

  • ファイルを参照している他のカードがあると、上書き後は再生が変わります（無音、または極小片）。参照をすべて削除してから上書きしてください
  • 上書き前に collection.media をバックアップ
  • これが 100MB 超のファイルを削除する唯一の方法です

14.8 より良い方法：最初から避ける

最も楽なのは最初からすべてのメディアファイルを 100MB 未満に保つことです。セクション 7 の ffmpeg パラメータなら、30 分のエピソードは通常 30〜50MB に収まります。100MB 問題は発生せず、セクション 13 の方法でクリーンアップできます。

15. 操作フロー総まとめ

15.1 初回インポート

  1. ffmpeg でメディアを圧縮：MP4 は iPhone 用、WebM は Windows 用

15.2 メディアの更新

  2. collection.media の旧ファイルを上書き
  3. apkg を再エクスポート
  4. iPhone へ転送
  5. 先に iPhone 上の旧 deck を削除
  6. 新しい apkg をインポート

15.3 メディアの追加

  1. 新しいファイルを命名規則に従って命名
  2. collection.media に配置
  3. sound フィールドに [sound:] 行を追加
  4. apkg を再エクスポート

15.4 特定メディアの削除

15.5 大ファイル（> 100MB）のクリーンアップ

16. よくある質問

Q1：apkg をインポートしたのに deck の中身が古いまま
iPhone に同名 deck が既にあるため AnkiMobile がインポートをスキップしました。先に旧 deck を削除してからインポートしてください。
Q2：apkg がエクスポート後に小さい。メディアが含まれていない
[sound:] 参照のファイル名が実ファイル名と完全に一致しているか（拡張子・大文字小文字を含めて）確認してください。Anki はカードから参照されているメディアのみを含めます。
Q3：Windows で動画が再生できない
Windows 版 Anki は WebM のみ対応です。ffmpeg で MP4 を WebM に変換してください： 
ffmpeg -i input.mp4 -vf "scale=-2:270" -c:v libvpx-vp9 -crf 35 -b:v 0 -c:a libopus -b:a 64k -ac 1 output.webm
Q4：iPhone で再生はできるがプログレスバーが飛ぶ
ファイルがシーク可能ではありません。ffmpeg で再エンコードし、必ず -movflags +faststart を付けてください。動画は main profile、音声は CBR MP3 または M4A。
Q5：[sound:] 参照を削除したのに「メディアをチェック」で見つからない
考えられる原因：
1. まだ他のカードが参照している。Anki の検索でファイル名を確認
2. apkg の再インポートが失敗した
3. ファイルが 100MB 超で「未使用」判定に参加しない。セクション 14 の方法を使用
Q6：カードを削除したのにメディアファイルが容量を占めたまま
カードを削除してもメディアは削除されません。sound フィールドの参照を削除し、再インポートして「メディアをチェック」を実行してください。
Q7：100MB 超のファイルが「メディアをチェック」に出てこない
Anki の設計です。100MB 超のファイルは別扱いで「未使用」判定に参加しません。セクション 14 の同名上書き法を使用してください。
Q8：AnkiWeb でメディアを同期できる？
できません。理由：
1. 数十 GB の帯域は現実的でない
2. 1 ファイル 100MB 超は同期不可
3. 無料の AnkiWeb には容量制限がある
メディアは apkg によるオフライン転送のみです。
Q9：学習カードの参照とメディアパックの [sound:] が衝突しない？
しません。メディアパックは転送媒体にすぎず、学習カードは同じファイルを参照しています。ファイルが iPhone 上にあれば、学習カードは見つけられます。
Q10：Windows と iPhone でファイル名の大文字小文字が一致しない
Windows は大文字小文字を区別しませんが iOS は区別します。問題を避けるには：
1. ファイル名はすべて小文字
2. [sound:] 参照もすべて小文字
3. Windows で File.mp4 と命名し、参照で file.mp4 と書かない
Q11：メディアパックのカードが復習に出てくる？
メディアパック deck に学習計画があると出てくることがあります。対処：
1. メディアパック deck の学習オプションを「一時停止」に
2. または復習計画から除外
3. またはカードを「保留」に設定
Q12：変換後、動画がぼやける
パラメータを調整：
1. -crf を下げる（例 24）→ 高画質、サイズ増
2. scale=-2:360 で解像度を上げる
3. -preset を slow にしてエンコードを細かく
語学学習では字幕が読めれば十分です。
Q13：複数シーズンを 1 つの apkg にまとめてもいい？
可能ですが非推奨です。理由：
1. 1 つの apkg が大きいと転送・インポートが遅い
2. 1 シーズン更新時にパッケージ全体を再転送
3. クリーンアップの粒度が粗い
1 シーズン 1 apkg が最も柔軟です。
Q14：apkg を使わず iPhone にファイルを直接コピーできる？
できません。iOS サンドボックスでは AnkiMobile の collection.media は「ファイル」アプリに公開されていません。apkg が唯一信頼できる転送方法です。
Q15：iTunes ファイル共有に AnkiMobile が出てこない
確認：
1. iPhone に AnkiMobile がインストール済み
2. iPhone がロック解除され、このコンピュータを信頼している
3. iTunes がデバイスを認識している
4. AnkiMobile のファイル共有が有効（デフォルトで有効）
Q16：なぜ毎回 deck を削除してからインポートする必要がある？
AnkiMobile のインポート方針です。AnkiWeb 同期は差分式（更新時刻の比較）ですが、apkg インポートは「一括追加」です。同名ノートはスキップされるため、先に削除する必要があります。
Q17：クラウドからダウンロードした apkg が AnkiMobile で開けない
考えられる原因：
1. クラウドアプリに「他のアプリで開く」がない。「ファイル」アプリに保存してからタップ
2. apkg のダウンロードが不完全。再ダウンロード
3. AnkiMobile が古い。最新版へ更新
Q18：動画変換時に幅を指定する必要がある？
不要です。scale=-2:270 を使えば高さは 270 に固定され、幅はアスペクト比を保って自動計算されます。-2 は幅が偶数になることを保証します。元動画が 16:9、4:3、その他どの比率でも、ffmpeg が適切な幅を算出します。
