1. What this guide solves

On iPhone, Anki media files work completely differently than on desktop or Android. On desktop and Android, you can open the file manager and manipulate the media folder directly. On iPhone you can't — iOS sandboxing keeps AnkiMobile's media library completely closed to the user.

This creates several real problems:

  1. How do I get tens of GB of media onto my iPhone? AnkiWeb sync is out of the question. The only workable path is offline apkg packaging, transferred via iTunes File Sharing or cloud drives.
  2. How do I play video on Windows? Windows Anki only supports WebM, not MP4. So the same video needs two copies: MP4 for iPhone, WebM for Windows.
  3. How do I make media seek accurately on iPhone? Not every video format supports seeking. Files that don't meet the requirements play fine on iPhone but the progress bar jumps erratically.
  4. How do I delete media I've already imported? Anki's "Check Media" can clean unused media, but only if the file is no longer referenced by any [sound:] tag and is under 100MB.
  5. Why does importing an apkg always fail? Because a deck with the same name already exists on iPhone, and AnkiMobile won't overwrite it. You must delete the old deck first.

This guide gives a complete, actionable workflow for all of the above.

2. Platform differences

2.2 The usual approach on desktop & Android

  • Copy media files straight into collection.media
  • [sound:] references in cards find them automatically
  • Delete = just delete the file
  • Replace = just overwrite the file
  • Check Media works normally

2.3 The iPhone problem

This guide focuses on iPhone / iPad. Desktop and Android users can operate the media folder directly; they only need to mind the Windows WebM limit.

iPhone sandboxing means:

  • No file system access → you can't copy, delete, or replace files manually
  • The only media transfer channel is apkg → media must be packaged to get in
  • [sound:] is the only way to make Anki pack a file into an apkg
  • Deleting media relies on "Check Media", triggered by removing the [sound:] reference
  • You must delete the old deck before importing an apkg, or the import is skipped

3. Windows video format limit

Windows Anki only supports WebM video, not MP4. This is a limitation of the Windows Anki playback engine, unrelated to iPhone.

3.1 Why this limit exists

Anki on Windows uses QtWebEngine (based on Chromium). Chromium on Windows doesn't ship with the H.264 decoder by default (patent licensing), so MP4 won't play. WebM uses VP8/VP9, which is open and free, so it's supported.

3.2 Impact on workflow

The same video needs two versions:

PlatformVideo formatCodec
iPhone / iPad / Android / macOSMP4H.264 + AAC
WindowsWebMVP8/VP9 + Vorbis/Opus

3.3 How media pack decks are split

This is why media packs are grouped by format. Example with Seinfeld:

0. Resources/
├── MP4 Seinfeld/     (for iPhone / Android / macOS)
│   ├── Seinfeld S01 Mp4
│   ├── Seinfeld S02 Mp4
│   └── ...
└── WEBM Seinfeld/    (for Windows)
    ├── Seinfeld S01 Webm
    ├── Seinfeld S02 Webm
    └── ...

The two decks are prepared independently, exported to separate apkg files, and transferred to the respective platforms.

3.4 Audio is not affected

Audio has fewer restrictions on Windows — both MP3 and M4A play. So MP3 series only need one copy.

4. Core mechanism: [sound:]

4.1 Common misconception

Many people think [sound:] is for controlling playback. In the media transfer scenario, its real purpose is:

To make Anki include the corresponding media file when exporting an apkg.

4.2 Why it's required

When exporting an apkg, Anki scans all [sound:] and <img> references in cards and collects the media files those references point to. Files that aren't referenced — Anki has no way to know they belong to this deck, so it won't pack them.

For tens of GB of media this is critical:

  • AnkiWeb sync is impossible (bandwidth, 100MB per-file limit)
  • apkg is the only reliable bulk offline transfer method
  • And apkg can only declare media via [sound:]

4.3 Three roles of [sound:]

RoleDescription
Transfer declarationTells Anki to pack these files into the apkg
Cleanup switchRemoving [sound:] and re-importing marks the file as "unused", so Check Media can delete it
Overwrite triggerWhen overwriting a same-named file, Anki only notices files referenced by [sound:]

4.4 [sound:] does not control playback

Playback is actually controlled by the card template's JavaScript (see VlsPlayer Series / Notes guides). Here [sound:] is only a "file list".

5. Media pack deck structure

5.1 Design principles

  • One deck per series: easy to export, transfer, and clean individually
  • One card per season for series with season numbers
  • One card for the whole series when there's no season number
  • Group by format: MP3 / MP4 / WEBM separated for platform-specific use
  • Deck and field names in pure English: avoid Unicode path issues

5.2 Recommended structure (with seasons)

Example with Seinfeld:

0. Resources/
├── MP4 Seinfeld/
│   ├── Seinfeld S01 Mp4   (Card 1, sound field lists all S01 episodes)
│   ├── Seinfeld S02 Mp4   (Card 2, sound field lists all S02 episodes)
│   ├── Seinfeld S03 Mp4
│   ├── ...
│   └── Seinfeld S09 Mp4
└── WEBM Seinfeld/
    ├── Seinfeld S01 Webm
    └── ...

5.3 Recommended structure (no seasons)

Example with Atomic Habits:

0. Resources/
├── MP3 Atomic Habits      (one deck, one card)
├── MP3 CWE                (one deck, one card)
├── MP4 DDM
└── MP4 Friends

5.4 Card fields

Each note has two fields:

FieldContent
FrontOne line of plain text, e.g. Seinfeld S02 Mp4, used as identifier
soundOne [sound:xxx] per line, listing all media for this card

5.5 sound field examples

With seasons (Seinfeld S02):

[sound:sf_s02e01.mp4]
[sound:sf_s02e02.mp4]
[sound:sf_s02e03.mp4]
...
[sound:sf_s02e12.mp4]

Without seasons (CWE):

[sound:cwe_01.mp4]
[sound:cwe_02.mp4]
[sound:cwe_03.mp4]
...
Put each [sound:] on its own line for readability and easy editing. Don't dump them into a single line — it's hard to maintain later.

5.6 Why one card per season

BenefitExplanation
Size controlOne season's apkg isn't too big, transfers more reliably
Independent updateUpdating one season only re-exports that one card
Independent cleanupCleanup granularity is per-season
Clear namingFront field shows the season at a glance

6. File naming rules

6.1 Two naming patterns

Depending on whether the content has seasons:

Without seasons

prefix_episode.ext

Examples:

cwe_01.mp4
cwe_02.mp4
atomic_habits_00.mp3
atomic_habits_01.mp3

With seasons

prefix_s##e##.ext

Examples:

sf_s02e01.mp4
sf_s02e02.mp4
sf_s02e12.mp4

6.2 Rules

ItemRule
PrefixSeries abbreviation, 2–4 lowercase letters, e.g. sf, cwe, ah
SeparatorUnderscore _
Seasons + two-digit zero-padded number, e.g. s01, s02 (with seasons only)
Episodee + two-digit zero-padded number, e.g. e01, e12 (with seasons only)
Episode (no season)Two or three-digit zero-padded, e.g. 01, 001
ExtensionUniform; don't mix within a series
ForbiddenChinese, spaces, uppercase, special chars

6.3 Choosing digit count

  • Under 100 episodes → two digits (01 ~ 99)
  • Over 100 episodes → three digits (001 ~ 999)
  • Digits must be uniform, or sorting breaks: _9.mp4 sorts after _10.mp4

6.4 Same series, multiple formats

sf_s02e01.mp4   (iPhone / Android / macOS)
sf_s02e01.webm  (Windows)
sf_s02e01.mp3   (audio)

Same filename, different extension. References in cards stay consistent; just swap extensions per platform.

6.5 Consistency with VlsPlayer Series cards

This naming convention must match the Series card Timeline field's concatenation rule. In the Series card code:

filename = prefix + "_" + (season == "" ? episode : "s" + season + "e" + episode) + ext
  • No season → cwe_01.mp4
  • With season → sf_s02e01.mp4
The [sound:] reference in the media pack deck, the Series card's Timeline field, and the actual filename must all match exactly, or the card won't find the file.

6.6 Batch-generating [sound:] references

With seasons (Bash, 12 episodes per season):

for i in $(seq -w 1 12); do echo "[sound:sf_s02e${i}.mp4]"; done

Without seasons:

for i in $(seq -w 1 30); do echo "[sound:cwe_${i}.mp4]"; done

Paste the output straight into the sound field.

7. Compress & convert with ffmpeg

7.1 Why compression is required

  • Raw video can be tens of GB; the iPhone can't hold it
  • Anki has a 100MB per-file processing limit
  • AnkiMobile is sluggish loading large files
  • For language learning you only need readable subtitles and visible mouth shapes — picture detail doesn't matter

7.2 Video compression: specify height only

You don't need to specify width — use -2 and let ffmpeg compute it:

MP4 (iPhone / Android / macOS)

ffmpeg -i input.mkv \
  -vf "scale=-2:270" \
  -c:v libx264 -profile:v main -level 3.0 -preset fast -crf 28 \
  -c:a aac -b:a 64k -ac 1 \
  -movflags +faststart \
  output.mp4

WebM (Windows)

ffmpeg -i input.mkv \
  -vf "scale=-2:270" \
  -c:v libvpx-vp9 -crf 35 -b:v 0 \
  -c:a libopus -b:a 64k -ac 1 \
  output.webm

What scale=-2:270 means:

  • Height fixed at 270
  • Width computed automatically, preserving aspect ratio
  • -2 ensures the width is even (encoder requirement)

270 is fine for both iPhone and desktop — subtitles and mouth shapes are clear. Let ffmpeg handle the width; you don't care whether the source is 16:9 or 4:3.

7.3 Audio compression

Recommended: M4A

ffmpeg -i input.wav \
  -c:a aac -b:a 64k -ac 1 \
  -movflags +faststart \
  output.m4a

If you must use MP3, use CBR (constant bitrate):

ffmpeg -i input.wav \
  -c:a libmp3lame -b:a 64k -ac 1 \
  output.mp3
Don't add -q:a — that produces VBR (variable bitrate). VBR MP3 without a Xing header seeks inaccurately on iPhone.

7.4 Key parameters

ParameterPurpose
scale=-2:270Fixed height 270, width auto even
-profile:v mainH.264 main profile, iOS compatible
-level 3.0Compatibility margin
-crf 28Quality/size balance point; higher gets blurry
-b:a 64k -ac 1Mono audio, 64 kbps
-movflags +faststartMP4-only. Moves moov to the front; critical for accurate seek on iPhone.

WebM doesn't need -movflags +faststart — that's MP4-only.

7.5 If still too big

Further compression:

  • -crf 32 — one notch lower quality
  • scale=-2:180 — height to 180
  • -r 20 — frame rate to 20 fps
  • -b:a 48k — audio to 48 kbps

7.6 Batch conversion scripts

Windows batch (convert all mkv in a folder to mp4):

for %%f in (*.mkv) do (
  ffmpeg -i "%%f" -vf "scale=-2:270" ^
    -c:v libx264 -profile:v main -level 3.0 -preset fast -crf 28 ^
    -c:a aac -b:a 64k -ac 1 ^
    -movflags +faststart "%%~nf.mp4"
)

Same folder, to webm:

for %%f in (*.mkv) do (
  ffmpeg -i "%%f" -vf "scale=-2:270" ^
    -c:v libvpx-vp9 -crf 35 -b:v 0 ^
    -c:a libopus -b:a 64k -ac 1 ^
    "%%~nf.webm"
)

8. Media must be seekable

8.1 What "seekable" means

Seeking means the player can jump to any point in the file and start playing. On iPhone, AVFoundation's seek support depends on the container format and metadata layout.

If a file isn't seekable you'll see:

  • It plays, but the progress bar is inaccurate
  • Jumping to the middle stalls or snaps back to start
  • Multiple [sound:] in sequence: the second starts at the wrong position
  • Looping starts offset

8.2 Seekability by format

FormatSeekable conditionWhen unmet
MP4 / M4Amoov atom at start of fileMust read the whole file before seeking; large files practically unseekable
WebMiOS AVFoundation support incompleteCan't seek on iPhone; fine on Windows
MP3 (VBR)Requires Xing/Info headerSeek position inaccurate
MP3 (CBR)Naturally seekable—
OGG / OpusiOS native unsupportedWon't play at all
AVI / MKV / WMV / FLViOS native unsupportedWon't play at all
H.264 + AAC in MP4Most stable—

8.3 Four rules for seekability

  1. On iPhone: video as MP4 (H.264 + AAC); audio as M4A or CBR MP3
  2. -movflags +faststart puts moov at the front — without it, large files can't seek
  3. Video profile must not be too new; baseline / main are safest
  4. Audio sample rate uniform at 44.1 kHz or 48 kHz

8.4 How to verify

Use ffprobe to check moov position:

ffprobe -v trace -i output.mp4 2>&1 | grep -E "type:'moov'|type:'mdat'"

If moov comes before mdat, faststart was applied.

8.5 One-liner summary

On iPhone: video as H.264 main profile + AAC in MP4, must include -movflags +faststart; on Windows: video as VP9/VP8 + Opus/Vorbis in WebM. All audio as AAC M4A, or CBR MP3.

9. Export to apkg

9.1 Desktop preparation

  1. Put all converted media files into collection.media
  2. Open the media pack deck (e.g. MP4 Seinfeld)
  3. Verify the [sound:] references in the sound field match the actual files
  4. Use Anki's "Check Media" to confirm all references resolve

9.2 Export

  1. In the deck list, right-click the target deck → Export
  2. Choose "Anki Deck Package (.apkg)"
  3. Check "Include media"
  4. Pick a save location
If you only want to export one series or one season, make sure only that deck is selected — don't choose "All Decks". Exporting per season gives more reliable transfers and imports.

9.3 Verify the package

  • apkg size should be close to the total of the media files
  • If the apkg is noticeably small, media wasn't included — check the [sound:] references
  • Open the apkg with 7-Zip (it's a zip) and confirm collection.media contains files

10. Transfer to iPhone

What you transfer is the apkg file itself, not synced media. Media is packed inside the apkg and transferred in one shot, bypassing AnkiWeb.

10.1 Three options

MethodBest forPros
iTunes / Finder File SharingWindows / Mac, preferredWired, most stable, no size limit
Cloud driveNo cable availableUpload then download on iPhone, convenient
AirDropMac, small-to-medium apkgWorks offline, fast
USB driveLarge apkg (> 5GB)No network needed, most stable

10.2 iTunes / Finder File Sharing (preferred)

Most common method — no network dependency, no apkg size limit.

Windows (iTunes)

  1. Connect iPhone to PC with a cable
  2. Open iTunes, click the device icon
  3. Go to "File Sharing"
  4. In the app list, select AnkiMobile
  5. Click "Add File" and choose the apkg
  6. iTunes copies the apkg to AnkiMobile's Documents folder
  7. On iPhone, open AnkiMobile — the apkg appears in the import list

macOS (Finder)

  1. Connect iPhone to Mac with a cable
  2. Open Finder, click iPhone in the sidebar
  3. Go to the "Files" tab
  4. In the app list, select AnkiMobile
  5. Drag the apkg into the file list
  6. On iPhone, open AnkiMobile to import

10.3 Cloud drive

Common options: iCloud Drive, OneDrive, Google Drive, Baidu Netdisk, Nutstore.

  1. Upload the apkg from your computer
  2. On iPhone, open the cloud app and download the apkg
  3. Tap the apkg → open with AnkiMobile
  4. Or save to the "Files" app first, then tap it to import
With Chinese cloud drives like Baidu Netdisk, you may need "Open with another app" and choose AnkiMobile. iOS hands the file over to AnkiMobile.

10.4 AirDrop (Mac users)

  1. Right-click the apkg on Mac → Share → AirDrop
  2. Select iPhone
  3. Tap "Accept" on iPhone
  4. iOS asks which app to open with — choose AnkiMobile

10.5 USB drive (large files)

  1. Copy the apkg onto a USB-C or Lightning USB drive
  2. Plug the drive into the iPhone
  3. Open the "Files" app, enter the USB drive
  4. Tap the apkg → open with AnkiMobile

10.6 Transfer time reference

11. Import: delete old deck first

This is the most common pitfall. If a deck with the same name already exists on iPhone, importing the apkg fails or is skipped. You must delete the old deck first.

11.1 Why delete first

When importing an apkg, AnkiMobile's policy for same-named decks is to skip already-existing notes, not overwrite. This means:

  • Same-named deck exists → new notes won't be imported
  • Existing notes won't be updated
  • Media files won't be replaced

Result: you import the new apkg, but iPhone still shows the old content.

11.2 Correct import procedure

  1. In AnkiMobile, find the old deck
  2. Long-press the deck → Delete (or swipe to delete)
  3. Confirm the deletion
  4. Tap the apkg file → open with AnkiMobile
  5. AnkiMobile shows a confirmation with the deck name and card count
  6. Tap "Import" and wait

11.3 Will deleting the deck lose progress?

  • If it's a media pack deck (one card, never reviewed), no impact
  • If a study card references the media, deleting the media pack deck doesn't affect it
  • Deleting a study deck loses its scheduling progress — verify before doing so

11.4 Bulk deletion

To update multiple season decks:

  1. Delete all decks to be updated in one pass
  2. Then import the new apkg files one by one

11.5 Verify success

  • Open the newly imported deck and check the card count
  • Look at the sound field of the media pack card — confirm [sound:] entries play
  • Open a study card, play the media, drag the progress bar to verify seek

11.6 Post-import cleanup

Once imported, you can delete the transferred apkg copies (on the USB drive, cloud drive, iTunes) to reclaim space.

12. Update media

12.1 When an update is needed

  • A video segment was cut incorrectly — re-cut it
  • Compression parameters were wrong — re-compress
  • Subtitle timeline changed — regenerate media
  • New episodes were added

12.2 Update workflow

  1. Generate the new media files on desktop
  2. Keep filenames unchanged, overwrite the old files in collection.media
  3. Verify the sound field references need no changes (filename unchanged)
  4. Re-export the apkg with "Include media" checked
  5. Transfer to iPhone
  6. Delete the old deck on iPhone first
  7. Import the new apkg
Media doesn't sync. Updates only happen through "delete old deck → re-import apkg". There's no such thing as syncing one file.

12.3 Adding new media

  1. Name the new file per the convention, e.g. sf_s02e13.mp4
  2. Put it in collection.media
  3. Append [sound:sf_s02e13.mp4] at the end of the sound field
  4. Re-export the apkg
  5. Delete the old deck on iPhone
  6. Import the new apkg

12.4 Renaming files

Renaming is high-risk — old files linger on iPhone. Avoid unless necessary. If you must:
1. Name the new file per the convention
2. Update card references
3. Re-export apkg
4. Delete the old deck and re-import
5. Clean up the old files using section 13

13. Delete specific media files

This trick is the core of the whole guide: delete the [sound:] reference to trigger Anki's "Check Media" cleanup of that file on iPhone.

13.1 How it works

Anki's "Check Media" scans the whole media library and finds files that are not referenced by any card, lists them under "unused files", and lets you delete them.

So you just need to:

  1. Remove the corresponding [sound:xxx.mp4] from the card field
  2. Re-export the apkg and import on iPhone (delete old deck first)
  3. Run "Check Media" in AnkiMobile
  4. The file appears under "unused files" and can be deleted

13.2 Full steps

Step 1: Remove the reference from the sound field

In desktop Anki, open the media pack deck's card and delete the [sound:xxx.mp4] line from the sound field.

Step 2: Confirm no other references exist

Use Anki's search to look for xxx.mp4 across the whole collection:

Search box: xxx.mp4

If there are still results, other cards are using it and you can't delete it.

Step 3: Re-export the apkg

Re-export the media pack deck. Since the reference is gone, Anki won't include the file.

Step 4: Transfer to iPhone

Send via iTunes File Sharing / cloud drive / AirDrop / USB.

Step 5: Delete the old deck on iPhone first

Find the old deck in AnkiMobile and delete it.

Step 6: Import the new apkg

Tap the new apkg and import with AnkiMobile.

Step 7: Run "Check Media"

Run "Check Media" in AnkiMobile (or desktop Anki). The file now has no references and appears under "unused files".

Step 8: Delete the unused file

Confirm and delete. Space is reclaimed.

13.3 Why this works

AnkiMobile's "Check Media" scans the local media library against card references and finds orphan files. Once a file is no longer referenced, it's listed as unused regardless of size.

13.4 Notes

  • Requires the file to be under 100MB. Files over 100MB don't participate in the "unused" check — see section 14
  • After removing the reference, the card will show "media missing" when playing that segment — expected
  • If you don't want the missing-media warning, also delete the card or clean it up
  • Back up the apkg before proceeding
  • If iPhone's "Check Media" doesn't find the file, the import may have failed — re-import

13.5 Bulk deletion

To remove multiple files, delete all corresponding [sound:] lines at once, re-export the apkg, import, then run "Check Media" once.

14. Clean up files over 100MB

14.1 The problem

If a media file is over 100MB, even after you delete the card that references it, the file remains in the media library and cannot be removed via "Check Media → Delete unused files".

14.2 Root cause

Anki's "Check Media" treats files over 100MB specially:

  • They're grouped separately under "Files over 100MB"
  • They don't participate in the "unused file" determination
  • So no matter whether any card still references it, the built-in tool won't delete it

The origin of this design is AnkiWeb's 100MB per-file sync limit. Anki assumes such files need manual handling.

14.3 The workaround

Overwrite the big file with a same-named tiny file, dropping it below 100MB. Anki then treats it like a normal file, and if no card references it, it becomes deletable via "unused files".

14.4 Full steps

Step 1: Remove card references

In desktop Anki, remove the [sound:xxx.mp4] reference from the card field, or delete the whole card.

Step 2: Prepare a tiny same-named file

Create a small file with the same name, well under 100MB.

Windows:

type nul > xxx.mp4

Or use ffmpeg to generate 1 second of silence:

ffmpeg -f lavfi -i anullsrc=r=44100:cl=mono -t 1 -c:a aac -movflags +faststart xxx.mp4

Step 3: Overwrite the original in collection.media

Open desktop Anki's media folder (Tools → Check Media → View Files), copy the tiny file in and overwrite the big one.

Step 4: Re-export apkg

Re-export the series (or media pack deck) with "Include media" checked.

Step 5: Transfer to iPhone and re-import

Send via iTunes File Sharing / cloud drive.

Delete the old deck on iPhone first, then import the new apkg. The tiny same-named file overwrites the big one on iPhone.

Step 6: Run Check Media

The file is now under 100MB and appears under "unused files". Delete it and reclaim space.

14.5 Why same-name overwrite works

Anki's media library is keyed by filename. When the same name is used, Anki notices during import that a file with that name already exists and replaces it with the new one. The old big file is gone.

14.6 Preconditions

  • The card must no longer reference the file; otherwise Anki treats it as "in use" and won't delete it even after shrinking
  • Do the overwrite on desktop — you can't access AnkiMobile's media folder directly
  • If the file on iPhone isn't replaced, the import probably failed; re-import

14.7 Warnings

  • If any card still references the file, overwriting it changes playback (silence or tiny snippet). Clear all references first
  • Back up collection.media before overwriting
  • This is the only way to remove a file over 100MB

14.8 Better: avoid it from the start

The easiest approach is to keep every media file under 100MB from the beginning. With the ffmpeg parameters in section 7, a 30-minute episode typically lands at 30–50MB. Then you never hit the 100MB problem and can clean up using section 13.

16. FAQ

Q1: After importing the apkg, the deck still shows old content
A deck with the same name already exists on iPhone, so AnkiMobile skipped the import. Delete the old deck first, then import.
Q2: The apkg is tiny after export — media wasn't included
Check whether the [sound:] reference filename matches the actual file exactly (extension and case). Anki only packs media that cards reference.
Q3: Video won't play on Windows
Windows Anki only supports WebM. Convert MP4 to WebM with ffmpeg: 
ffmpeg -i input.mp4 -vf "scale=-2:270" -c:v libvpx-vp9 -crf 35 -b:v 0 -c:a libopus -b:a 64k -ac 1 output.webm
Q4: Media plays on iPhone but the progress bar jumps around
The file isn't seekable. Re-encode with ffmpeg, must include -movflags +faststart, video main profile, audio CBR MP3 or M4A.
Q5: Removed the [sound:] reference, but Check Media doesn't find the file
Possible causes:
1. Another card still references it — search the filename in Anki
2. The apkg re-import failed
3. The file is over 100MB and doesn't participate in the unused check — use section 14
Q6: Deleted the card, but the media file still takes up space
Deleting the card doesn't delete the media. Remove the reference in the sound field, re-import, and run Check Media.
Q7: Files over 100MB aren't in Check Media
That's Anki's design: files over 100MB are grouped separately and excluded from the unused check. Use the same-name overwrite method in section 14.
Q8: Can AnkiWeb sync media?
No. Reasons:
1. Tens of GB is impossible
2. Files over 100MB can't sync
3. Free AnkiWeb has storage limits
So media only travels via apkg offline.
Q9: Will the study cards' references conflict with the media pack's [sound:]?
No. The media pack is just a transfer vehicle; study cards reference the same files. Once the files are on iPhone, study cards find them.
Q10: Filename case differs between Windows and iPhone
Windows filesystems are case-insensitive; iOS is case-sensitive. To avoid problems:
1. Filenames all lowercase
2. [sound:] references also all lowercase
3. Don't name a file File.mp4 on Windows and write file.mp4 in the reference
Q11: Will media pack cards show up during review?
If the media pack deck has a study plan, possibly. To prevent it:
1. Set the media pack deck's options to "paused"
2. Or exclude it from the review plan
3. Or mark its cards as "suspended"
Q12: Video got blurry after conversion
Tune the parameters:
1. Lower -crf (e.g. 24) for better quality, larger file
2. Raise scale=-2:360 for higher resolution
3. Change -preset to slow for finer encoding
For language learning, readable subtitles are enough.
Q13: Can I package multiple seasons into one apkg?
Yes, but not recommended:
1. A single large apkg makes transfer and import slow
2. Updating one season means re-transferring the whole package
3. Cleanup granularity is too coarse
One apkg per season is the most flexible.
Q14: Can I skip apkg and copy files to iPhone directly?
No. iOS sandboxing keeps AnkiMobile's collection.media out of the Files app. apkg is the only reliable transfer method.
Q15: AnkiMobile doesn't appear in iTunes File Sharing
Check:
1. AnkiMobile is installed on the iPhone
2. iPhone is unlocked and trusts this computer
3. iTunes detects the device
4. AnkiMobile has file sharing enabled (on by default)
Q16: Why do I have to delete the deck every time I update?
That's AnkiMobile's import policy. AnkiWeb sync is incremental (compares modification times), but apkg import is bulk-add. Same-named notes are skipped, so you must delete first.
Q17: apkg downloaded from cloud drive won't open with AnkiMobile
Possible causes:
1. The cloud app doesn't offer "Open with another app" — save to Files first
2. The apkg download was incomplete — re-download
3. AnkiMobile is outdated — update
Q18: Do I have to specify width when converting video?
No. Use scale=-2:270 — height is fixed at 270 and width is auto-computed to preserve aspect ratio. -2 ensures the width is even. Whether the source is 16:9, 4:3, or something else, ffmpeg calculates a suitable width.
