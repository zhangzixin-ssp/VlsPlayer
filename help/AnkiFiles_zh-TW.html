1. 本說明書解決什麼問題

Anki 的媒體檔案在 iPhone 上的操作，和桌面、Android 完全不同。桌面和 Android 可以直接開啟檔案管理器操作媒體目錄，iPhone 不行——iOS 的沙箱機制讓 AnkiMobile 的媒體庫對使用者完全封閉。

這導致幾個現實問題：

  1. 怎麼把幾十 G 的媒體傳進 iPhone？ 走 AnkiWeb 同步不可能，只能透過 apkg 離線打包，再借助 iTunes 檔案共享或網路硬碟傳輸。
  2. Windows 上影片怎麼播放？ Windows 版 Anki 只支援 WebM，不支援 MP4。所以同一個影片要準備兩份，給 iPhone 用 MP4，給 Windows 用 WebM。
  3. 怎麼讓媒體在 iPhone 上精準定位？ 不是所有影片格式都支援 seek。不滿足條件的檔案在 iPhone 上播放正常但進度條亂跳。
  4. 怎麼刪除已經匯入的媒體？ Anki 的「檢查媒體」可以清理未使用的媒體，但前提是檔案中已經不再有 [sound:] 參照，而且檔案小於 100MB。
  5. 為什麼匯入 apkg 總是失敗？ 因為 iPhone 上已存在同名 deck，AnkiMobile 不會自動覆蓋，必須先刪除舊 deck 再匯入。

本說明書針對這幾個問題，給出完整的、可操作的工作流程。

2. 三個平台的本質區別

2.1 對照表

平台媒體檔案存取方式影片格式是否需要媒體包
Windows直接開啟 collection.media 資料夾，增刪改都行僅 WebM不需要
macOS直接開啟 collection.media 資料夾，增刪改都行MP4 / WebM 皆可不需要
Android直接存取 AnkiDroid 的媒體目錄，增刪改都行MP4不需要
iPhone / iPad沙箱封閉，無法直接存取檔案系統MP4必須

2.2 桌面與 Android 的常規做法

  • 直接把媒體檔案複製進 collection.media 資料夾
  • 卡片裡的 [sound:] 參照自動找到檔案
  • 刪除就是直接從資料夾刪
  • 覆蓋就是直接取代檔案
  • 檢查媒體能正常工作

2.3 iPhone 的困境

本說明書主要面向 iPhone / iPad。桌面和 Android 使用者可以直接操作媒體資料夾，只需要注意 Windows 的 WebM 格式限制。

iPhone 的沙箱機制意味著：

  • 無法存取檔案系統 → 沒法手動複製、刪除、取代
  • 唯一的檔案傳輸通道是 apkg → 媒體必須被打包才能進手機
  • [sound:] 是讓 Anki 把檔案裝進 apkg 的唯一手段
  • 刪除媒體要依賴 Anki 的「檢查媒體」，透過刪除 [sound:] 參照觸發
  • 匯入 apkg 前必須先刪除同名 deck，否則匯入會被跳過

3. Windows 影片格式限制

Windows 版 Anki 只支援 WebM 影片，不支援 MP4。這是 Windows 版 Anki 的播放引擎限制，和 iPhone 無關。

3.1 為什麼會有這個限制

Anki 在 Windows 上用的是 QtWebEngine（基於 Chromium），Chromium 在 Windows 上預設不帶 H.264 解碼器（因為專利授權問題），所以 MP4 播不了。WebM 用的是 VP8/VP9 編碼，開源免費，所以被支援。

3.2 對工作流程的影響

同一個影片，需要在兩個平台上有兩份：

平台影片格式編碼
iPhone / iPad / Android / macOSMP4H.264 + AAC
WindowsWebMVP8/VP9 + Vorbis/Opus

3.3 媒體包 deck 的分工

這就是為什麼媒體包要按格式分組。以 Seinfeld 為例：

0. Resources/
├── MP4 Seinfeld/     （給 iPhone / Android / macOS 用）
│   ├── Seinfeld S01 Mp4
│   ├── Seinfeld S02 Mp4
│   └── ...
└── WEBM Seinfeld/    （給 Windows 用）
    ├── Seinfeld S01 Webm
    ├── Seinfeld S02 Webm
    └── ...

兩個 deck 是獨立準備的，各自匯出 apkg，各自傳輸到對應平台。

3.4 音訊不受此限制

音訊格式在 Windows 上限制較少，MP3、M4A 都能播。所以 MP3 系列只需要一份。

4. 核心機制：[sound:] 的作用

4.1 常見的誤解

很多人以為 [sound:] 是用來控制播放的。在媒體傳輸場景裡，它真正的作用是：

讓 Anki 在匯出 apkg 時，把對應的媒體檔案打包進去。

4.2 為什麼必須用它

Anki 匯出 apkg 時，會掃描卡片裡所有 [sound:] 和 <img> 參照，把這些參照指向的媒體檔案收集起來打包。沒有被參照的檔案，Anki 根本不知道它們屬於這個牌組，就不會打包。

對於幾十 G 的媒體，這尤其關鍵：

  • AnkiWeb 同步不可能（流量、100MB 單檔限制）
  • apkg 是唯一可靠的批次離線傳輸方式
  • 而 apkg 只能透過 [sound:] 宣告媒體

4.3 [sound:] 的三重角色

角色說明
傳輸宣告告訴 Anki 這些檔案要打進 apkg
清理開關從卡片裡刪掉 [sound:] 參照，重新匯入後，對應媒體變成「未使用」，可被「檢查媒體」刪除
覆蓋觸發同名檔案覆蓋時，Anki 只識別 [sound:] 參照的檔案是否更新

4.4 [sound:] 不負責播放控制

真正的播放控制由卡片模板的 JavaScript 完成（見 VlsPlayer Series / Notes 說明書）。[sound:] 在這裡只是一個「檔案清單」。

5. 媒體包 deck 的結構

5.1 設計原則

  • 每個系列一個 deck：便於單獨匯出、單獨傳輸、單獨清理
  • 每季一張卡片：有季編號的系列，每季單獨一張卡片
  • 無季編號的系列，整個系列一張卡片
  • 按格式分組：MP3 / MP4 / WEBM 分開，便於按平台選用
  • deck 名和欄位用純英文：避免路徑的 Unicode 問題

5.2 建議結構（有季編號）

以 Seinfeld 為例：

0. Resources/
├── MP4 Seinfeld/
│   ├── Seinfeld S01 Mp4   （卡片 1，sound 欄位列 S01 的所有集）
│   ├── Seinfeld S02 Mp4   （卡片 2，sound 欄位列 S02 的所有集）
│   ├── Seinfeld S03 Mp4
│   ├── ...
│   └── Seinfeld S09 Mp4
└── WEBM Seinfeld/
    ├── Seinfeld S01 Webm
    └── ...

5.3 建議結構（無季編號）

以 Atomic Habits 為例：

0. Resources/
├── MP3 Atomic Habits      （一個 deck，一張卡片）
├── MP3 CWE                （一個 deck，一張卡片）
├── MP4 DDM
└── MP4 Friends

5.4 卡片欄位結構

每張筆記有兩個欄位：

欄位名內容
Front一行純文字，如 Seinfeld S02 Mp4，用作識別符
sound一行一個 [sound:xxx]，列出這張卡片對應的所有媒體

5.5 sound 欄位範例

有季編號的（Seinfeld S02）：

[sound:sf_s02e01.mp4]
[sound:sf_s02e02.mp4]
[sound:sf_s02e03.mp4]
...
[sound:sf_s02e12.mp4]

無季編號的（CWE）：

[sound:cwe_01.mp4]
[sound:cwe_02.mp4]
[sound:cwe_03.mp4]
...
每個 [sound:] 佔一行，便於閱讀和手動增刪。不要寫成一行連續串，那樣以後不好維護。

5.6 為什麼每季一張卡片

優點說明
體積可控一季的 apkg 不會太大，傳輸更穩
獨立更新更新某一季時，只重新匯出那一張卡片
獨立清理清理時按季清理，粒度清晰
命名清晰Front 欄位一眼看出是哪一季

6. 檔案命名規範

6.1 兩種命名格式

根據內容是否有季編號，命名分兩種：

無季編號

前綴_集號.副檔名

範例：

cwe_01.mp4
cwe_02.mp4
atomic_habits_00.mp3
atomic_habits_01.mp3

有季編號

前綴_s季號e集號.副檔名

範例：

sf_s02e01.mp4
sf_s02e02.mp4
sf_s02e12.mp4

6.2 規則

項目規則
前綴系列縮寫，2-4 字母小寫，如 sf、cwe、ah
分隔符底線 _
季號s + 兩位補零，如 s01、s02（僅在有季編號時使用）
集號e + 兩位補零，如 e01、e12（僅在有季編號時使用）
集號（無季）兩位或三位補零，如 01、001
副檔名統一，同一系列內不混用
禁止中文、空格、大寫、特殊字元

6.3 序號位數怎麼定

  • 少於 100 集 → 兩位（01 ~ 99）
  • 多於 100 集 → 三位（001 ~ 999）
  • 位數必須統一，否則排序會亂：_9.mp4 會排在 _10.mp4 後面

6.4 同一系列多種格式

sf_s02e01.mp4   （iPhone / Android / macOS）
sf_s02e01.webm  （Windows 專用）
sf_s02e01.mp3   （音訊）

檔名相同，副檔名不同。這樣卡片裡的參照結構一致，按平台替換副檔名即可。

6.5 和 VlsPlayer Series 卡片的一致性

這個命名規範必須和 Series 卡 Timeline 欄位的拼接規則一致。Series 卡程式碼裡的拼接邏輯是：

檔名 = 前綴 + "_" + (季號為空 ? 集號 : "s" + 季號 + "e" + 集號) + 副檔名
  • 季號為空 → cwe_01.mp4
  • 季號非空 → sf_s02e01.mp4
媒體包 deck 裡的 [sound:] 參照、Series 卡 Timeline 欄位、實際檔名，三者必須完全一致，否則卡片找不到檔案。

6.6 批次產生 [sound:] 參照

有季編號（Bash，假設一季 12 集）：

for i in $(seq -w 1 12); do echo "[sound:sf_s02e${i}.mp4]"; done

無季編號：

for i in $(seq -w 1 30); do echo "[sound:cwe_${i}.mp4]"; done

輸出直接貼進 sound 欄位。

7. 用 ffmpeg 壓縮與轉換

7.1 為什麼必須壓縮

  • 原始影片動輒幾十 G，iPhone 裝不下
  • Anki 對單檔有 100MB 的處理限制
  • AnkiMobile 載入大檔案會卡頓
  • 語言學習只需要看清字幕和嘴型，畫面細節不重要

7.2 影片壓縮：只需指定高度

轉影片時不需要指定寬度，用 -2 讓 ffmpeg 自動計算：

MP4（iPhone / Android / macOS）

ffmpeg -i input.mkv \
  -vf "scale=-2:270" \
  -c:v libx264 -profile:v main -level 3.0 -preset fast -crf 28 \
  -c:a aac -b:a 64k -ac 1 \
  -movflags +faststart \
  output.mp4

WebM（Windows 專用）

ffmpeg -i input.mkv \
  -vf "scale=-2:270" \
  -c:v libvpx-vp9 -crf 35 -b:v 0 \
  -c:a libopus -b:a 64k -ac 1 \
  output.webm

scale=-2:270 的含義：

  • 高度固定 270
  • 寬度自動計算，保持長寬比
  • -2 保證寬度是偶數（編碼器要求）

270 對 iPhone 和桌面都夠用，字幕和嘴型都能看清。寬度交給 ffmpeg，不用管原始是 16:9 還是 4:3。

7.3 音訊壓縮

推薦 M4A：

ffmpeg -i input.wav \
  -c:a aac -b:a 64k -ac 1 \
  -movflags +faststart \
  output.m4a

如果必須用 MP3，用 CBR（固定位元率）：

ffmpeg -i input.wav \
  -c:a libmp3lame -b:a 64k -ac 1 \
  output.mp3
不要加 -q:a，那會產生 VBR（可變位元率）。VBR MP3 除非有 Xing 標頭，否則 iPhone 上 seek 不準。

7.4 關鍵參數說明

參數作用
scale=-2:270高度固定 270，寬度自動取偶數
-profile:v mainH.264 主流 profile，iOS 相容
-level 3.0相容性保險
-crf 28畫質/體積平衡點，再高就糊
-b:a 64k -ac 1音訊單聲道 64kbps
-movflags +faststartMP4 專有，moov 移到檔案開頭，iPhone 上能精準 seek 的關鍵

WebM 不需要 -movflags +faststart，那是 MP4 專有參數。

7.5 如果還是太大

進一步壓縮：

  • -crf 32 畫質再降一檔
  • scale=-2:180 高度降到 180
  • -r 20 幀率降到 20fps
  • -b:a 48k 音訊降到 48kbps

7.6 批次轉換腳本

Windows 批次檔（同一目錄下所有 mkv 轉 mp4）：

for %%f in (*.mkv) do (
  ffmpeg -i "%%f" -vf "scale=-2:270" ^
    -c:v libx264 -profile:v main -level 3.0 -preset fast -crf 28 ^
    -c:a aac -b:a 64k -ac 1 ^
    -movflags +faststart "%%~nf.mp4"
)

同樣目錄轉 webm：

for %%f in (*.mkv) do (
  ffmpeg -i "%%f" -vf "scale=-2:270" ^
    -c:v libvpx-vp9 -crf 35 -b:v 0 ^
    -c:a libopus -b:a 64k -ac 1 ^
    "%%~nf.webm"
)

8. 媒體必須可精準定位

8.1 什麼是「可定位」

定位（seek）指的是播放器跳到檔案的任意時間點開始播放。iPhone 上的 AVFoundation 對 seek 的支援取決於容器格式和元資料結構。

如果檔案不可定位，會出現：

  • 播放能播，但滑動進度條不準
  • 跳到中間位置會卡住或跳回開頭
  • 多個 [sound:] 連續播放時，第二個開始位置錯亂
  • 循環播放的起點偏移

8.2 各格式的可定位條件

格式可定位條件不滿足時的現象
MP4 / M4Amoov atom 必須在檔案開頭必須讀完整個檔案才能 seek，大檔案幾乎無法定位
WebMiOS AVFoundation 支援不完整iPhone 上無法 seek；Windows 上正常
MP3 (VBR)必須有 Xing/Info 標頭seek 位置不準
MP3 (CBR)天然可定位—
OGG / OpusiOS 原生不支援完全不能播
AVI / MKV / WMV / FLViOS 原生不支援完全不能播
H.264 + AAC in MP4最穩—

8.3 保證可定位的四條規則

  1. iPhone 上的影片用 MP4（H.264 + AAC），音訊用 M4A 或 CBR MP3
  2. -movflags +faststart 讓 moov 在開頭，否則大檔案無法 seek
  3. 影片 profile 不能太新，baseline / main 最穩
  4. 音訊取樣率統一 44.1kHz 或 48kHz

8.4 檢查方法

用 ffprobe 檢查 moov 位置：

ffprobe -v trace -i output.mp4 2>&1 | grep -E "type:'moov'|type:'mdat'"

如果先出現 moov 再出現 mdat，說明已經 faststart 處理過。

8.5 一句話總結

iPhone 上的影片轉成 H.264 main profile + AAC 的 MP4，必須加 -movflags +faststart；Windows 上的影片轉成 VP9/VP8 + Opus/Vorbis 的 WebM。所有音訊轉成 AAC 的 M4A，或 CBR MP3。

9. 打包成 apkg

9.1 桌面側準備

  1. 把所有轉換好的媒體檔案放進 collection.media 資料夾
  2. 開啟媒體包 deck（如 MP4 Seinfeld）
  3. 確認 sound 欄位裡的 [sound:] 參照與實際檔案一致
  4. 可以用 Anki 的「檢查媒體」確認所有參照都能找到檔案

9.2 匯出 apkg

  1. 在牌組列表中，右鍵目標 deck → 匯出
  2. 選擇「Anki 牌組包（.apkg）」格式
  3. 勾選「包含媒體檔案」
  4. 選擇儲存位置
如果只想匯出某個系列或某一季，一定要在匯出時選中那個 deck，不要選「所有牌組」。每季單獨匯出，傳輸和匯入都更穩。

9.3 打包後的驗證

  • apkg 檔案大小應該接近所有媒體檔案的總和
  • 如果 apkg 明顯偏小，說明媒體沒被打包，檢查 [sound:] 參照是否正確
  • 可以用 7-Zip 開啟 apkg（本質是 zip），確認裡面的 collection.media 有檔案

10. 傳輸到 iPhone

傳輸的是 apkg 檔案本身，不是同步媒體。媒體打包在 apkg 裡，一次性傳給 iPhone，不經過 AnkiWeb。

10.1 三種方式

方式適用場景優點
iTunes / Finder 檔案共享Windows / Mac 使用者，首選有線傳輸，最穩定，無大小限制
網路硬碟無傳輸線時上傳後 iPhone 下載，方便
AirDropMac 使用者，中小 apkg無網也可，速度快
USB 隨身碟直插大 apkg（> 5GB）不依賴網路，最穩定

10.2 iTunes / Finder 檔案共享（首選）

這是最常用的方式，因為它不依賴網路，不受 apkg 大小限制。

Windows（iTunes）

  1. 用傳輸線連接 iPhone 和電腦
  2. 開啟 iTunes，點擊裝置圖示
  3. 進入「檔案共享」
  4. 在 App 列表裡選擇 AnkiMobile
  5. 點擊「加入檔案」，選擇 apkg
  6. iTunes 把 apkg 傳到 AnkiMobile 的 Documents 目錄
  7. 在 iPhone 上開啟 AnkiMobile，apkg 出現在匯入列表裡

macOS（Finder）

  1. 用傳輸線連接 iPhone 和 Mac
  2. 開啟 Finder，側邊欄點擊 iPhone
  3. 進入「檔案」標籤頁
  4. 在 App 列表裡選擇 AnkiMobile
  5. 把 apkg 拖進檔案列表
  6. 在 iPhone 上開啟 AnkiMobile 匯入

10.3 網路硬碟

常用網路硬碟：iCloud Drive、OneDrive、Google Drive、百度網盤、堅果雲。

  1. 電腦上把 apkg 上傳到網路硬碟
  2. iPhone 上開啟對應網路硬碟 App，下載 apkg
  3. 點擊 apkg → 用 AnkiMobile 開啟
  4. 或者先存到「檔案」App，再點擊匯入

11. 匯入：先刪除舊 deck

這是最容易踩的坑。如果 iPhone 上已經有同名 deck，直接匯入 apkg 會失敗或被跳過。必須先刪除舊的 deck，再匯入新的。

11.1 為什麼必須先刪除

AnkiMobile 在匯入 apkg 時，對同名 deck 的處理策略是跳過已存在的筆記，而不是覆蓋。這意味著：

  • 同名 deck 已存在 → 新筆記不會匯入
  • 已存在的筆記不會被更新
  • 媒體檔案也不會被取代

結果就是：你匯入了新 apkg，但 iPhone 上還是舊的內容。

11.2 正確的匯入流程

  1. 在 AnkiMobile 裡找到對應的舊 deck
  2. 長按 deck → 刪除（或滑動刪除）
  3. 確認刪除
  4. 點擊 apkg 檔案 → 用 AnkiMobile 開啟
  5. AnkiMobile 彈出確認框，顯示 deck 名和卡片數量
  6. 點擊「匯入」，等待完成

11.3 刪除 deck 會不會影響學習進度

  • 如果這個 deck 是媒體包（只有一張卡片，從不複習），刪除無影響
  • 如果是正式學習卡片參照了媒體，刪除媒體包 deck 不會影響正式卡片
  • 但刪除正式學習 deck 會遺失學習進度，操作前要確認清楚

11.4 批次刪除

如果要更新多個季的 deck，可以：

  1. 一次性刪除所有要更新的 deck
  2. 再逐個匯入新的 apkg

11.5 驗證匯入成功

  • 開啟新匯入的 deck，檢查卡片數量
  • 檢視 media pack 卡片的 sound 欄位，確認 [sound:] 都顯示為可播放
  • 開啟一張正式學習卡片，播放媒體，拖動進度條驗證可定位

11.6 匯入後的清理

apkg 已經匯入 iPhone 後，可以刪除傳輸過程中的 apkg 副本（隨身碟裡的、網路硬碟裡的、iTunes 裡的），釋放空間。

12. 更新媒體

12.1 什麼情況下需要更新

  • 發現某段影片切錯了，重新切
  • 壓縮參數不對，重新壓
  • 字幕時間軸調整，媒體需要重新產生
  • 增加了新的集數

12.2 更新流程

  1. 桌面側產生新的媒體檔案
  2. 保持檔名不變，覆蓋 collection.media 裡的舊檔案
  3. 確認 sound 欄位裡的參照不需要改（如果檔名沒變）
  4. 重新匯出 apkg，勾選「包含媒體檔案」
  5. 傳到 iPhone
  6. 先在 iPhone 上刪除對應的舊 deck
  7. 再匯入新的 apkg
媒體不走同步，更新只能透過「刪除舊 deck → 重新匯入 apkg」完成。不存在「只同步一個檔案」這種操作。

12.3 增加新媒體

  1. 新檔案按命名規範命名，如 sf_s02e13.mp4
  2. 放進 collection.media
  3. 在 sound 欄位末尾追加一行 [sound:sf_s02e13.mp4]
  4. 重新匯出 apkg
  5. 刪除 iPhone 上的舊 deck
  6. 匯入新的 apkg

12.4 改檔名

改檔名是高風險操作，因為舊檔案會殘留在 iPhone 上。除非必要，不要改檔名。要改的話：
1. 新檔名按規範命名
2. 卡片參照同步改
3. 重新匯出 apkg
4. 刪除舊 deck 再匯入
5. 舊檔案用第 13 節的方法清理

13. 刪除指定媒體檔案

這一節的技巧是整份說明書的核心：透過刪除 [sound:] 參照，觸發 Anki 的「檢查媒體」來清理 iPhone 上的媒體檔案。

13.1 原理

Anki 的「檢查媒體」會掃描整個媒體庫，找出沒有被任何卡片參照的檔案，列在「未使用檔案」裡，允許使用者刪除。

因此，只要：

  1. 從卡片欄位裡刪掉對應的 [sound:xxx.mp4]
  2. 重新匯出 apkg 並匯入 iPhone（記得先刪除舊 deck）
  3. 在 AnkiMobile 裡執行「檢查媒體」
  4. 該檔案就會出現在「未使用檔案」列表裡，可以刪除

13.2 完整操作步驟

步驟 1：刪除 sound 欄位裡的參照

在桌面 Anki 裡，開啟媒體包 deck 的卡片，從 sound 欄位裡刪掉要清理的 [sound:xxx.mp4] 行。

步驟 2：確認參照已經被清掉

用 Anki 的搜尋功能，在整個收藏裡搜尋 xxx.mp4，確認沒有其他卡片還在參照這個檔案。

在 Anki 搜尋框輸入：xxx.mp4

如果還有結果，說明其他卡片還在用，不能刪。

步驟 3：重新匯出 apkg

把媒體包 deck 重新匯出 apkg。此時因為 sound 欄位裡已經沒有該參照，Anki 打包時不會包含該檔案。

步驟 4：傳到 iPhone

透過 iTunes 檔案共享 / 網路硬碟 / AirDrop / 隨身碟傳到 iPhone。

步驟 5：先刪除 iPhone 上的舊 deck

在 AnkiMobile 裡找到對應的舊 deck，刪除。

步驟 6：匯入新的 apkg

點擊新的 apkg，用 AnkiMobile 匯入。

步驟 7：執行「檢查媒體」

在 AnkiMobile 裡（或桌面 Anki 裡）執行「檢查媒體」。該檔案現在沒有任何參照，會出現在「未使用檔案」列表裡。

步驟 8：刪除未使用檔案

確認後刪除。空間釋放。

13.3 為什麼這個流程有效

AnkiMobile 的「檢查媒體」會掃描本機媒體庫，對照卡片參照，找出孤兒檔案。只要檔案不再被參照，無論它大小，都會被列為「未使用」。

13.4 注意事項

  • 前提是該檔案小於 100MB。超過 100MB 的檔案不參與「未使用」判定，見第 14 節
  • 刪除參照後，卡片上播放這段媒體會顯示「媒體缺失」，這是預期的
  • 如果不想讓卡片顯示缺失提示，應該同時刪掉卡片，或把卡片也一起清理
  • 操作前備份 apkg，以防誤刪
  • 如果 iPhone 上的「檢查媒體」沒有找到該檔案，可能是匯入沒成功，重新匯入一次

13.5 批次刪除多個媒體

如果要清理多個檔案，一次性從 sound 欄位裡刪掉所有對應的 [sound:] 行，然後重新匯出 apkg。匯入後執行一次「檢查媒體」就能全部清理。

14. 清理超過 100MB 的大檔案

14.1 問題描述

如果媒體檔案超過 100MB，即使使用者已經刪掉了參照它的卡片，檔案仍然會留在媒體庫裡，無法透過「檢查媒體 → 刪除未使用檔案」清除。

14.2 根本原因

Anki 的「檢查媒體」對超過 100MB 的檔案有特殊處理：

  • 它們被單獨歸入「超過 100MB 的檔案」列表
  • 不參與「未使用檔案」的判定
  • 所以無論卡片是否還參照它，都無法透過內建功能刪除

這個設計的根源是 AnkiWeb 對單一媒體檔案有 100MB 的同步上限。Anki 假設這類檔案需要使用者手動處理。

14.3 解決思路

用一個同名的小檔案覆蓋掉大檔案，讓它降到 100MB 以下。此時 Anki 會把它當作普通檔案處理，如果卡片已經不再參照它，就會被正常列為「未使用檔案」，可以刪除。

14.4 完整操作步驟

步驟 1：刪掉卡片參照

在桌面 Anki 裡，去掉卡片欄位中對該媒體的 [sound:xxx.mp4] 參照，或者直接刪掉整張卡片。

步驟 2：準備同名小檔案

建立一個與原檔案同名的小檔案，大小遠小於 100MB。

Windows：

type nul > xxx.mp4

或者用 ffmpeg 產生 1 秒靜音片段：

ffmpeg -f lavfi -i anullsrc=r=44100:cl=mono -t 1 -c:a aac -movflags +faststart xxx.mp4

步驟 3：覆蓋 collection.media 裡的原檔案

開啟桌面 Anki 的媒體資料夾（工具 → 檢查媒體 → 檢視檔案），把剛準備的小檔案複製進去，覆蓋原大檔案。

步驟 4：重新匯出 apkg

把這個系列（或這個媒體包 deck）重新匯出 apkg，勾選「包含媒體檔案」。

步驟 5：傳到 iPhone 重新匯入

透過 iTunes 檔案共享 / 網路硬碟傳到 iPhone。

先在 iPhone 上刪除對應的舊 deck，然後用 AnkiMobile 匯入新的 apkg。同名小檔案會覆蓋手機上的大檔案。

步驟 6：執行檢查媒體

此時這個檔案已經小於 100MB，會出現在「未使用檔案」列表裡。刪除它，空間釋放。

14.5 為什麼同名覆蓋有效

Anki 的媒體庫是按檔名管理的。用同名檔案覆蓋後，Anki 在匯入 apkg 時發現同名檔案已存在，會用新檔案取代舊檔案。這樣舊的大檔案就被取代掉了。

14.6 前提條件

  • 卡片必須先不再參照該檔案，否則即使檔案變小了，Anki 仍認為它是「使用中」，不會刪除
  • 覆蓋操作要在桌面完成，因為 iPhone 端無法直接存取 AnkiMobile 的媒體資料夾
  • 如果 iPhone 上的檔案沒被取代，可能是匯入沒成功，重新匯入一次

14.7 注意事項

  • 如果這個檔案還有其他卡片在參照，覆蓋後播放效果會變（變成靜音或極小片段）。確保所有參照都已清掉再覆蓋
  • 覆蓋前備份 collection.media，以防誤操作
  • 這個方法是清理超過 100MB 大檔案的唯一途徑

14.8 更好的做法：從源頭避免

最省事的做法是從一開始就把每個媒體檔案壓到 100MB 以下。用第 7 節的 ffmpeg 參數，30 分鐘一集通常能壓到 30-50MB。這樣永遠不會遇到 100MB 問題，清理時直接用第 13 節的方法即可。

15.1 首次匯入

16. 常見問題

Q1：匯入 apkg 後，deck 裡還是舊內容
因為 iPhone 上已存在同名 deck，AnkiMobile 跳過了匯入。先在 iPhone 上刪除舊 deck，再匯入。
Q2：apkg 匯出後體積很小，媒體沒被包含
檢查 [sound:] 參照的檔名是否和實際檔名完全一致（包括副檔名和大小寫）。Anki 只打包能被卡片參照的媒體。
Q3：Windows 上影片播不了
Windows 版 Anki 只支援 WebM。用 ffmpeg 把 MP4 轉成 WebM： 
ffmpeg -i input.mp4 -vf "scale=-2:270" -c:v libvpx-vp9 -crf 35 -b:v 0 -c:a libopus -b:a 64k -ac 1 output.webm
Q4：iPhone 上媒體播放正常，但進度條亂跳
檔案不是「可定位」的。用 ffmpeg 重新轉，必須加 -movflags +faststart，影片用 main profile，音訊用 CBR MP3 或 M4A。
Q5：刪了 [sound:] 參照，但檢查媒體找不到該檔案
可能原因：
1. 還有其他卡片在參照該檔案。用 Anki 搜尋功能搜檔名確認
2. 重新匯入 apkg 時沒成功
3. 該檔案大於 100MB，不參與「未使用」判定，需要用第 14 節的方法
Q6：刪了卡片，但媒體檔案還在佔空間
刪卡片不會自動刪媒體。需要在 sound 欄位裡也刪掉參照，然後重新匯入並執行檢查媒體。
Q7：超過 100MB 的檔案，檢查媒體裡找不到
這是 Anki 的設計：超過 100MB 的檔案被單獨歸類，不參與「未使用」判定。用同名小檔案覆蓋法處理（第 14 節）。
Q8：能不能用 AnkiWeb 同步媒體？
不能。原因：
1. 幾十 G 的流量不可能
2. 單檔超過 100MB 無法同步
3. AnkiWeb 免費帳戶有容量限制
所以媒體只能透過 apkg 離線傳輸。
Q9：正式卡片的參照和媒體包的 [sound:] 會不會衝突
不會。媒體包只是一個「傳輸載體」，正式卡片的參照指向同一批檔案。檔案在 iPhone 上就位後，正式卡片就能找到。
Q10：檔名大小寫在 Windows 和 iPhone 上不一致
Windows 檔案系統不分大小寫，iOS 分。為避免問題：
1. 檔名全小寫
2. [sound:] 參照也用全小寫
3. 不要在 Windows 上命名成 File.mp4，再在參照裡寫成 file.mp4
Q11：媒體包 deck 裡的卡片會不會在複習時出現
如果媒體包 deck 有學習計畫，可能會出現。處理方法：
1. 把媒體包 deck 的學習選項設為「暫停」
2. 或者把媒體包 deck 從複習計畫中排除
3. 或者把媒體包 deck 裡的卡片設定成「已暫停」
Q12：ffmpeg 轉換後影片變糊了
調整參數：
1. -crf 降低（如 24），畫質提升，體積增大
2. scale=-2:360 高度提到 360，解析度提升
3. -preset 改為 slow，編碼更精細
語言學習場景下，只要字幕能看清就夠了。
Q13：多個季一起打包成一個 apkg 可以嗎
可以，但建議分開。原因：
1. 單個 apkg 太大會導致傳輸慢、匯入慢
2. 更新某一季時要重新傳整個大包
3. 清理時粒度太粗
每季一個 apkg 最靈活。
Q14：能不能不用 apkg，直接複製檔案到 iPhone
不能。iOS 沙箱機制下，AnkiMobile 的 collection.media 不暴露在檔案 App 裡。唯一可靠的傳輸方式是 apkg。
Q15：iTunes 檔案共享裡看不到 AnkiMobile
確認：
1. iPhone 上已安裝 AnkiMobile
2. iPhone 已解鎖並信任此電腦
3. iTunes 已識別到裝置
4. AnkiMobile 開啟了檔案共享（AnkiMobile 預設開啟）
Q16：為什麼每次更新都要刪 deck 再匯入
這是 AnkiMobile 的匯入策略。AnkiWeb 的同步是增量的（按修改時間比較），但 apkg 匯入不是增量，而是「批次新增」。同名筆記被跳過，所以只能先刪除再匯入。
Q17：網路硬碟下載的 apkg 用 AnkiMobile 打不開
可能原因：
1. 網路硬碟 App 沒提供「用其他應用程式開啟」的選項，先存到「檔案」App 再點擊
2. apkg 下載不完整，重新下載
3. AnkiMobile 版本太舊，升級到最新版
Q18：轉影片時一定要指定寬度嗎
不需要。用 scale=-2:270，高度固定 270，寬度自動計算，保持長寬比。-2 保證寬度是偶數。這樣不管原始影片是 16:9、4:3 還是其他比例，ffmpeg 都會自動算出合適的寬度。
